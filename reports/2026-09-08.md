## ECC 项目调研报告

### 项目定位

ECC 定位为「Agent Harness 性能优化系统」——一套横跨 Claude Code、Codex、Opencode、Cursor 等主流编码 Agent 工具的上层运行时配置与管理层，核心能力覆盖 Skills（技能包）、instincts（行为倾向）、memory（记忆）、security（安全）与 research-first 开发流程。它不解决模型能力问题，而是解决「同一套 Agent 工作流如何在多个 harness 之间复用、增强和治理」的问题，处于模型层之上的**工具层 / Agent 中间件层**。用 JavaScript 编写说明它更贴近开发者本地工作流而非服务端基础设施。

### 生态分析

**直接竞品/互补项目：**
- **obra/superpowers**：同属 Claude Code 技能框架赛道，是 ECC 在「技能包供给」维度的最直接对标项目
- **openai/skills 与 openai/plugins**：官方阵营的技能/插件生态，属于平台原生方案，与 ECC 构成「官方 vs 第三方横跨层」的竞争关系
- **mksglu/context-mode**：上下文/记忆管理方向，与 ECC 的 memory 模块互补，共现关键词中 rag、context 相关信号也印证了这一关联

**生态位置判断：** 以 254K Stars、38K Forks 的体量，ECC 在「跨 harness Agent 配置层」已明显处于**龙头位置**（其 README 中的 Trending of the Day 与全球排名徽章也佐证了头部曝光度）。Fork/Star 比 0.15 偏高，说明大量用户在 fork 后做个性化定制——这是典型的「平台型项目被二次开发」的特征，而非单纯的被动收藏。

**生态成熟度：** 成长期（快速增长但格局未定）。判断依据：技能层仍高度碎片化（superpowers、openai/skills、各种垂直 skills 仓库并存），多家 harness 尚未形成统一标准，官方玩家刚刚入场。这是增长最快、但标准之争未决的阶段。

### Issue 热点

**信息不足**——本次数据中未提供任何近期 Issue 标题，无法基于实际数据总结社区最关心的方向。唯一可从 README 间接观察到的信号是：项目维护了 13 种语言的本地化文档，暗示社区关注点具有强地域多样性，国际化用户的接入问题是潜在热点，但此判断缺乏 Issue 数据支撑，仅供参考。

### 机会缺口

1. **跨 harness 技能兼容性验证工具**：ECC 的核心卖点是「一套配置跑遍 Claude Code / Codex / Cursor / Opencode」，但从生态碎片化程度看（superpowers、openai/skills 各自为政），缺少一个独立的「技能包跨平台移植与兼容性测试」工具——自动检测某个 skill 在不同 harness 下的语法/能力差异并做适配。共现关键词中 cli、workflow 的密度也指向这一层。

2. **第三方技能包的安全审计层**：ECC 自带 security 模块，但 38K 个 fork 意味着大量社区衍生技能包在无准入审查的情况下流通。一个针对 skills 供应链的静态扫描/权限分析工具（类比 npm 生态的 audit）存在明确空白，且与项目声明的安全定位天然互补。

### 趋势预测

基于现有数据：254K Stars 的规模加上 Trending 徽章表明项目正处于爆发式增长期，38K Forks（Fork/Star 0.15）显示社区衍生行为活跃，这是典型的平台型项目早期扩张形态。未来 3-6 个月最可能的走向是：(1) 衍生技能包生态继续膨胀，fork 数量随之攀升，但会带来碎片化和质量参差的问题，反向强化上述兼容性/安全工具的缺口；(2) 随 openai/skills 等官方生态加码，「第三方横跨层」与「平台原生能力」的边界摩擦会加剧，ECC 需要靠跨平台中立性维持优势。**需要说明的局限**：由于缺少 Issue 活跃度和时间序列的 Star 增速数据，无法判断增长是处于加速还是见顶阶段，以上预测的置信度中等；机会评分 0.4 也提示该生态的工具层窗口正在收窄，新入场者应聚焦细分缺口而非正面竞争。

## coreyhaines31/marketingskills

### 项目定位

Marketing Skills 是一个面向 AI 编码代理（Claude Code、OpenAI Codex、Cursor、Windsurf 等）的**营销领域技能库**，遵循跨代理的 Agent Skills 规范，覆盖转化率优化（CRO）、文案、SEO、数据分析和增长工程。它在技术栈中处于 **Agent 生态的“能力注入层”**——不是模型也不是框架，而是把营销方法论打包成代理可加载的 skill，让技术型营销人员和创始人用编码代理执行营销工作。值得注意的是，该仓库同时是作者 Corey Haines（SaaS 营销圈知名人物）商业体系的流量入口（README 中导流至其代理服务、付费课程和 Magister 产品），具有强烈的“个人品牌 + 开源获客”属性。

### 生态分析

**关联项目：**
- **obra/superpowers** — 目前最知名的通用技能库，偏工程能力；marketingskills 是其在营销垂直领域的对应物
- **openai/skills / openai/plugins** — 平台方官方技能体系，代表分发渠道被平台收编的潜在压力
- **browser-use** — 互补关系：代理的浏览器执行层，SEO 审计、竞品分析类营销技能往往需要其配合落地

**生态位置：** 在“营销垂直技能”细分赛道中是明确的**龙头**（48.7k stars 远超同类垂直技能库）；但在整个 Agent Skills 生态中是**垂直挑战者**——底层规范和分发入口由 Anthropic/OpenAI 等平台方主导。

**成熟度判断：成长期。** Agent Skills 规范刚实现跨代理互通，技能库数量爆发（同域列表中已出现 superpowers、karpathy-skills 等多个策展型集合），但缺少统一的质量评估、发现与管理机制，是典型的成长期特征。

### Issue 热点

**信息不足**——提供的数据中无近期 Issue 标题，无法总结社区关注方向。但这个缺失本身是一个信号：如此规模的仓库若 issue 活跃度低，说明星标主要来自作者受众的传播型关注，而非开发者的深度使用和反馈。

### 机会缺口

1. **技能质量评估/测试层**：技能库爆发式增长，但没有任何基准或评测工具能判断一个 skill 的实际效果（如 CRO 技能产出的建议质量）。“技能的单元测试与基准评测”是当前生态的空白工具层。
2. **技能个性化适配工具**：0.15 的 Fork/Star 比表明绝大多数用户“拿来即用”而非改造。缺少帮助用户把通用营销技能快速参数化到自身品牌语气、分析栈（GA/GTM/特定 CMS）的定制中间层——这是被星标量掩盖但未被满足的真实需求。

### 趋势预测

48.7k stars 显示项目经历了由作者受众驱动的典型病毒式增长曲线，但 0.15 的 fork 率与缺失的 issue 活跃度表明社区参与是浅层的。未来 3-6 个月的保守预判：(1) **star 增速自然回落至平台期**，除非 Magister（作者的 CMO 代理产品）联动带来第二波传播；(2) **最大结构性风险是平台方收编**——若 OpenAI/Anthropic/Cursor 推出官方技能市场或原生营销能力增强，垂直技能库的分发优势和存在必要性都会被削弱；(3) **关键观察指标是 issue/PR 活跃度是否随 star 同步上升**——若持续脱节，项目将演变为个人品牌的营销资产而非社区工程，技能内容也会因缺乏贡献者而“陈旧化”。中等偏上的机会评分（0.4）与此一致：周边工具层（测试、定制、管理）存在窗口，但窗口期取决于技能规范本身的演化速度。

## openai/plugins

### 项目定位

openai/plugins 是 OpenAI 官方维护的 Codex 插件示例集合，定义了以 `.codex-plugin/plugin.json` 清单为核心的插件包结构（可组合 `skills/`、`.mcp.json`、`agents/`、`commands/`、`hooks.json` 等表面），并内置默认插件市场（`marketplace.json`）与 API-key 用户独立市场（`api_marketplace.json`）。它处于 AI 编程 Agent 技术栈的**工具层/扩展层**：向下依赖 Codex 运行时与 MCP 协议，向上为开发者提供把 Figma、Notion、Expo、Netlify 等外部能力接入 Agent 工作流的标准化封装。本质上，这是 Codex 插件生态的“官方种子仓库 + 规范参考实现”。

### 生态分析

**直接竞品/互补项目：**
- **openai/skills**：同一主体的姊妹项目，提供 Agent Skills 规范与技能集合，与本项目是“技能”与“插件”的分层互补关系。
- **obra/superpowers**：跨 Agent 的社区技能集合，代表第三方阵营对同一“可插拔能力”需求的回应，是潜在的规范竞争者。
- **multica-ai/andrej-karpathy-skills、coreyhaines31/marketingskills**：垂直领域技能包，说明社区正在围绕“技能分发”这一模式大量繁殖衍生仓库。

**生态位置：** 该项目是 Codex 插件生态的**官方锚点（龙头）**——它既定义规范又提供示例和市场入口，第三方难以在同一生态位取代。但它只是示例集而非运行时，真正的控制权在 Codex 本体手中。Fork/Star 比为 0.14，属于较高派生水平，说明大量用户以 fork 方式自建插件，生态正在从官方示范向社区自繁殖过渡。

**生态成熟度：** **成长期早段**。判据：市场机制刚建立（且存在双市场分裂迹象）、第三方技能仓库刚出现爆发式萌芽、尚未出现稳定的版本管理与质量分层机制。

### Issue 热点

**信息不足**——近期无 Issue 数据，无法从本项目直接提取社区关注方向。间接信号来自共现关键词（agent、cli、workflow、rag、api），可推断周边讨论集中在 Agent 工作流编排与 CLI 工具链集成上，但这一推断置信度有限。

### 机会缺口

1. **插件市场管理与兼容工具缺失**：仓库内同时存在 `marketplace.json` 和 `api_marketplace.json` 两套市场，暗示不同登录方式的用户看到不同插件目录，且示例无版本管理、依赖解析和质量分级机制。一个“插件发布/校验/版本管理 CLI + 跨市场目录聚合工具”是明显的空白。
2. **跨 Agent 技能/插件移植层**：`.codex-plugin` 清单是 Codex 专有格式，而 superpowers、karpathy-skills 等社区集合使用各自的技能组织方式，生态正在碎片化。一个能把技能在 Codex、Claude 等不同 Agent 格式间自动转换/同步的“可移植性工具层”，对应 0.39 的机会评分所指示的中等偏高工具层空间。

### 趋势预测

基于可观察数据：Fork/Star 0.14 的较高派生率 + 关联项目中技能类仓库的密集涌现，表明该生态处于社区自繁殖加速阶段。未来 3-6 个月最可能的发展路径是：(1) 第三方插件/技能仓库数量继续增长并出现整合压力，官方仓库的角色从“示例集”向“规范与市场入口”沉淀；(2) 双市场分裂和格式碎片化问题将随规模扩大而凸显，催生对统一发布与移植工具的需求。需说明的限制：本次数据未提供 star 时间序列和 Issue 活跃度，无法做定量的增长外推，以上判断基于结构性信号（fork 派生模式、关联生态繁殖密度）而非增速曲线，预测置信度中等。
